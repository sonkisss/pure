# 解决 macOS 文件监视限制问题

## ❌ 错误信息

```
Error: EMFILE: too many open files, watch
```

这是 macOS 系统默认的文件描述符限制太低导致的问题。

---

## ✅ 快速解决方案（临时，重启终端后失效）

### 步骤 1：打开一个新的终端窗口

关闭当前终端，打开一个**全新的终端窗口**（不要在 VS Code 的集成终端中）。

### 步骤 2：增加文件描述符限制

在新的终端中执行：

```bash
ulimit -n 10240
```

### 步骤 3：验证设置

```bash
ulimit -n
```

应该显示 `10240`

### 步骤 4：启动开发服务器

```bash
cd /Users/mac/Documents/cc/pure-admin-thin
pnpm dev
```

## 🔧 永久解决方案（推荐）

### 方法 1：修改 Shell 配置文件

根据您使用的 Shell 类型选择：

**如果使用 Zsh（macOS 默认）：**

```bash
echo 'ulimit -n 10240' >> ~/.zshrc
source ~/.zshrc
```

**如果使用 Bash：**

```bash
echo 'ulimit -n 10240' >> ~/.bash_profile
source ~/.bash_profile
```

### 方法 2：创建系统级配置（最彻底）

1. 创建 `/Library/LaunchDaemons/limit.maxfiles.plist` 文件：

```bash
sudo nano /Library/LaunchDaemons/limit.maxfiles.plist
```

2. 粘贴以下内容：

```xml
<?xml version="1.0" encoding="UTF-8"?>
<!DOCTYPE plist PUBLIC "-//Apple//DTD PLIST 1.0//EN" "http://www.apple.com/DTDs/PropertyList-1.0.dtd">
<plist version="1.0">
  <dict>
    <key>Label</key>
    <string>limit.maxfiles</string>
    <key>ProgramArguments</key>
    <array>
      <string>launchctl</string>
      <string>limit</string>
      <string>maxfiles</string>
      <string>65536</string>
      <string>200000</string>
    </array>
    <key>RunAtLoad</key>
    <true/>
    <key>ServiceIPC</key>
    <false/>
  </dict>
</plist>
```

3. 设置权限并加载：

```bash
sudo chown root:wheel /Library/LaunchDaemons/limit.maxfiles.plist
sudo chmod 644 /Library/LaunchDaemons/limit.maxfiles.plist
sudo launchctl load -w /Library/LaunchDaemons/limit.maxfiles.plist
```

4. **重启电脑**使配置生效。

## ⚠️ 常见问题

### Q1: 为什么在 VS Code 终端中不行？

**答**：VS Code 的集成终端可能继承了旧的环境变量。建议使用系统独立的终端应用。

### Q2: 重启电脑后又不行了？

**答**：临时方案会在终端关闭后失效。请使用"永久解决方案"中的方法。

### Q3: 执行 ulimit -n 10240 后还是报错？

**答**：

1. 确保在**新的**终端窗口中执行
2. 执行后用 `ulimit -n` 验证是否生效
3. 如果还是不行，尝试 `ulimit -n 65536`

### Q4: 端口 8848 已被占用？

**答**：查找并停止占用端口的进程：

```bash
# 查找占用 8848 端口的进程
lsof -ti:8848

# 停止进程（替换 PID 为上面查到的进程ID）
kill -9 PID
```

## 💡 为什么会出现这个问题？

macOS 默认的文件描述符限制很低（通常是 256 或 512），而现代前端项目（尤其是使用 Vite 的项目）需要监视大量文件：

- Vue 组件文件
- TypeScript 文件
- CSS/SCSS 文件
- 配置文件
- node_modules 中的文件

当项目文件过多时，就会超出系统限制，导致 `EMFILE` 错误。
