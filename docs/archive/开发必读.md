## 🚨 重要规则

### ⛔ 禁止创建新的.md文件

**所有开发记录必须写入 `CHANGELOG.md`，禁止创建新的独立.md文件！**

❌ **错误做法**:

```
创建文件：用户管理功能说明.md
创建文件：Bug修复-登录问题.md
创建文件：UI优化说明.md
```

✅ **正确做法**:

```
所有记录都追加到：CHANGELOG.md
```

### 📝 如何添加开发记录

1. 打开 `CHANGELOG.md`
2. 在顶部（`## 📋 目录` 之后）添加新的日期分组
3. 按格式记录功能、Bug修复或优化
4. 保存文件

**记录模板**:

```markdown
## YYYY-MM-DD

### ✨ 新功能

#### ✅ 功能标题

**功能描述**: 简要描述

**实现细节**:

- 详细说明1
- 详细说明2

**相关文件**: `path/to/file.vue`

---
```

## 🛠️ 开发流程

### 开发前

1. 阅读 `CHANGELOG.md` 了解最新开发进展
2. 确认要开发的功能没有重复
3. 在 `CHANGELOG.md` 的"待开发功能"区域添加TODO

### 开发中

1. 遵守代码规范（见 `.project-rules.md`）
2. 及时提交代码（遵守Git提交规范）
3. 记录重要的技术决策

### 开发后

1. **立即更新** `CHANGELOG.md`
2. 记录功能描述、实现细节、相关文件
3. 进行完整测试
4. 更新测试状态

## 🔍 快速查找

### 查找某个功能的实现

1. 打开 `CHANGELOG.md`
2. 使用 `Ctrl+F` / `Cmd+F` 搜索功能关键词
3. 查看"相关文件"定位代码

### 查找某个Bug的修复记录

1. 打开 `CHANGELOG.md`
2. 搜索"Bug修复"或Bug关键词
3. 查看修复方案和代码

### 查找某个UI优化

1. 打开 `CHANGELOG.md`
2. 搜索"UI优化"或组件名称
3. 查看优化细节

---

## 💡 最佳实践

1. ✅ 每天开始工作前，先看一遍 `CHANGELOG.md` 的最新更新
2. ✅ 开发完成后，立即更新 `CHANGELOG.md`
3. ✅ 遇到问题时，先在 `CHANGELOG.md` 中搜索是否有相关记录
4. ✅ 代码提交时，在commit message中引用 `CHANGELOG.md` 的记录
5. ✅ 定期回顾 `CHANGELOG.md`，熟悉项目的演进历史
